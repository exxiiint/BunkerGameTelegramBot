# Telegram-бот для игры «Бункер» (MVP)

Учебный проект: Telegram-бот, который ведёт партии игры «Бункер» в **базовом режиме**:
- лобби по коду (создать / присоединиться)
- раздача скрытых карточек игрокам
- 5 раундов: открытие карты Бункера → круг раскрытия карт персонажей → голосования по таблице (4–16 игроков)
- тайное голосование через бота
- сохранение истории партий в PostgreSQL (таблица `game_events`)

> ⚠️ Тексты карточек в этом проекте **самописные**.

---

## Быстрый старт

### 1) Создайте бота в Telegram
Через @BotFather получите токен и запишите его в `.env`.

### 2) Подготовьте env
```bash
cp .env.example .env
# откройте .env и вставьте BOT_TOKEN
```

### 3) Запуск
```bash
docker compose up --build
```

Бот начнёт polling (long polling).

---

## Как играть (MVP-логика)

1. `/start`
2. Кнопки:
   - **Создать лобби**
   - **Присоединиться** (ввести 6-значный код)
3. В лобби все игроки нажимают **Готов**.
4. Владелец нажимает **Старт игры**.
5. Бот раздаёт карты в личку каждому игроку и ведёт раунды:
   - активный игрок открывает карту Бункера (кнопка)
   - затем игроки по очереди раскрывают по 1 карте (в 1 раунде — только Профессия)
   - если в раунде есть голосование — бот разошлёт бюллетени в личку, и когда все проголосуют — исключит игрока

Полезные команды:
- `/cards` — показать ваши карты и что раскрыто
- `/history` — последние события активной партии

## CI / GitHub Actions

В проекте настроен автоматический запуск тестов с использованием GitHub Actions.

Все unit- и integration-тесты выполняются в CI при:
- push в репозиторий
- pull request

Конфигурационные файлы CI находятся в каталоге:

.github/workflows/

В рамках CI:
- поднимается необходимое окружение (Docker, PostgreSQL);
- выполняются unit-тесты;
- выполняются интеграционные тесты с использованием PostgreSQL;
- проверяется корректность сборки проекта.

Таким образом, все тесты в проекте запускаются автоматически при каждом изменении кода, что обеспечивает стабильность и корректность работы системы.

## Архитектура (C4: Context / Container)

### Context
Игроки взаимодействуют с ботом через Telegram. Бот хранит состояние и историю партий в PostgreSQL.

### Container
- `bot` — aiogram-приложение, игровая логика, обработчики, работа с БД
- `postgres` — база данных (партии, лобби, голоса, события)

---

## DB-структура (кратко)

Основные таблицы:
- `users` — Telegram пользователи
- `lobbies`, `lobby_members` — лобби и участники
- `games`, `game_players` — партии и игроки в партиях
- `player_cards` — карты персонажей
- `bunker_cards` — карты бункера
- `votes` — голоса
- `game_events` — история действий (event log)

---

## Масштабирование x10 (идея)

При росте нагрузки:
- поднимать несколько реплик `bot` (stateless), состояние в Postgres
- защищать критические операции (голосование/изгнание) транзакциями (`SELECT ... FOR UPDATE`)
- при необходимости: read-replica для отчётов/истории + партиционирование `game_events`
